Jotbook / jot

一个存你自己命令的笔记本。它解决的是检索问题，不是生成问题 —— 命令你早就知道、早就跑通过，你只是不想再翻一遍聊天记录。

版本 0.1.0 日期 2026-08-19 栈 Rust 1.97 · MSVC 后端 无 内置 13 本 · 460 条 冷启动 38ms
01

定位与边界

Jotbook 把一条命令拆成三样东西：文本模板、变量、注入通道。它把最终文本打进你正在用的那个输入框，然后就退场 —— 回车永远由你按。

命令行是旗舰场景，但数据模型里不出现 “shell” 这个概念，所以 SQL、kubectl、curl、正则、连接串全部免费适用。

做这些

  • 本地 Markdown 笔记本，可 git 同步，不装 Jotbook 也能读
  • 三层变量：每次问的、Profile 常量、命令动态生成的
  • 把结果注入当前 shell 缓冲区 / 任意焦点窗口 / 剪贴板，用户可选
  • 社区笔记本靠 GitHub 仓库分发，零账号零服务器
  • CLI 与 GUI 同源，各自独立可用

明确不做

  • 不做终端模拟器。不接管 PTY，不自己跑命令 —— 那是 Warp 和 Atuin Desktop 的赛道，工作量差一个数量级
  • 不做执行引擎：无编排、无步骤依赖、无重试
  • 不做账号 / 云同步 / 团队空间 —— 用 git
  • 不做 AI 生成命令 —— 你已经有 Claude Code 了；Jotbook 存的是已经验证过的那条
  • 不做密钥管理：明确拒收 secrets，只支持引用 {{@env.X}}
  • 不把 cmd.exe 当一等公民：它没有任何行编辑 hook，只保证键盘模拟能用
为什么这一节最重要

这是个单人项目。上面「不做」的六条，每一条都是别人一定会来提的 issue。第一天就写进 README，之后照着它无情地关。

02

系统分层

两个前端不通过 IPC 互相依赖。理由很硬：shell widget 模式下 CLI 是每次按键被重新拉起一次的，必须能在没有 GUI 的机器上独立工作，也必须冷启动够快（见 D-10）。它们唯一的耦合点是磁盘上那批 .md 文件。

03

数据格式

一个笔记本 = 一个 .md 文件。YAML frontmatter 声明变量，## 标题是条目名，标题下的正文是说明，代码块是命令本身。在 GitHub 上直接可读，用 VSCode / vim 编辑毫无障碍。

~/.jot/notebooks/local/my-servers.mdspec_version 1
---
name: my-servers
description: 我的服务器与服务
tags: [ops, deploy]
vars:
  service:
    desc: systemd 服务名
    from: profile              # ← 从当前 Profile 取，见 §3.2
  host:
    desc: 目标主机
    from: shell                # ← 动态候选列表
    cmd: grep '^Host ' ~/.ssh/config | awk '{print $2}'
  since:
    desc: 日志起始时间
    from: ask
    options: ["10 min ago", "1 hour ago", "today"]
---

## 重启后端服务

改完 appsettings 之后必须重启，改 nginx 不用。

```sh @platform=linux @confirm @tags=deploy
sudo systemctl restart {{service}}
```

## 跟踪服务日志

```sh @platform=linux @remote
journalctl -u {{service}} --since "{{since}}" -f
```

## 登上生产机

```sh
ssh {{host}}
```

3.1　代码块属性

属性作用缺省
@platform=windows / linux / macos，多值逗号分隔；非当前平台的条目从搜索结果里隐藏any
@confirm危险命令。注入前多一步确认弹窗，且在列表里带警示色关
@remote标记「预期在 SSH 之后使用」。会禁用该条目的 from: shell 变量，因为动态候选会在本地求值 —— 这是个隐蔽的正确性陷阱关
@id=稳定标识，用于 jot run <id> 和跨笔记本引用标题 slug
@lang（即围栏语言）sh/ps1 走 shell 通道；sql 等直接走键盘模拟或剪贴板；同时决定高亮sh

3.2　变量的三层

语法统一是 {{name}}，行内默认值写 {{name=默认}}，字面量大括号转义为 \{{。

来源行为典型用途
ask执行时提问，可带静态候选分支名、时间窗口
profile从当前 Profile 直接取值，不打断流程kestrel-orders-api.service
shell跑一条命令生成候选列表，模糊搜索里选systemd 服务、docker 容器、k8s pod
@内置{{@cwd}} {{@clipboard}} {{@git.branch}} {{@date}} {{@env.X}}上下文填充
~/.jot/profiles.toml本地，永不进 git
[prod]
service = "kestrel-orders-api.service"
host    = "prod-01"
db      = "orders"

[dev]
service = "kestrel-orders-api.service"
host    = "dev-01"
db      = "orders_dev"

# jot use prod   → 全局切换
# 生产 Profile 建议置顶显示为警示色，避免手滑
格式一旦有用户就改不动了

所以 M0 阶段只给自己用，格式先跑满一个月再公开。frontmatter 里从第一版就写 spec_version，给未来的迁移留门。

04

注入层

这是整个项目唯一真正难的部分，也是全部平台差异的所在地。设计的起点是你提的那个需求 —— 能跑 ssh xxx 然后接着用。这一句话决定了架构。

如果自己 spawn 子进程执行命令，就必须实现 PTY、ANSI 解析、滚动缓冲、窗口尺寸协商 —— 那是在造终端。而注入模型天然绕开它：把 ssh prod-01 打进你自己的终端，你按回车，之后的一切与 Jotbook 无关。

但代价藏在下一步：进去以后，本地 shell 已经不读输入了，widget 通道当场失效。

4.1　通道能力矩阵

通道机制精度穿透 SSH失败模式
A · Buffer CLI 打到 stdout，shell widget 写回行缓冲 精确 否 几乎不会失败
B · Keystroke Win SendInput · mac CGEventPost · X11 XTEST 较高 是 焦点竞态、IME、Wayland、EDR 拦截
C · Clipboard arboard 写剪贴板 + 提示 较高 是 覆盖用户剪贴板（可选恢复）

降级链

  1. 环境变量 JOT_WIDGET=1 → A（说明是 shell 自己拉起的）
  2. 否则键盘模拟可用且焦点窗口不是 Jotbook 自己 → B
  3. 否则 → C，并明确告诉用户「已复制，按 Ctrl+V」

用户可以在设置里把默认通道钉死，也可以在 Palette 里用 Tab 临时切换 —— 你原话「用户自己选择」就是这一条。

实现时会踩的三个坑

  • 多行必须用 bracketed paste（\e[200~ … \e[201~）包住，否则中间的换行被终端当成执行 —— 这是 B 通道最容易出的安全事故。
  • Wayland 设计上禁止全局合成输入。ydotool 要 uinput 权限，wtype 只支持 wlroots。espanso 至今没解决，你也不会。提前写进 README，直接降级到 C。
  • Windows 上先试 WriteConsoleInput（配合 AttachConsole）再退回 SendInput：前者是直接写目标控制台的输入缓冲，比合成键盘事件可靠得多，也不容易被 EDR 盯上。这条值得花半天验证。

4.2　Widget 协议

沿用 fzf 那套约定：TUI 画到 stderr/tty，结果打到 stdout，退出码 0 = 替换缓冲区，非 0 = 用户取消，缓冲区原样不动。这样 widget 脚本可以极短，也不需要任何 IPC。

shell/jot.psm1 · PowerShellPSReadLine
Set-PSReadLineKeyHandler -Chord 'Ctrl+g' -ScriptBlock {
    $line = $null; $cursor = $null
    [Microsoft.PowerShell.PSConsoleReadLine]::GetBufferState([ref]$line, [ref]$cursor)
    $env:JOT_WIDGET = '1'
    $out = jot pick --widget --line "$line"
    if ($LASTEXITCODE -eq 0 -and $out) {
        [Microsoft.PowerShell.PSConsoleReadLine]::RevertLine()
        [Microsoft.PowerShell.PSConsoleReadLine]::Insert($out)
    }
}
shell/jot.bash · shell/jot.zshreadline / zle
# bash
__jot_widget() {
  local out; out=$(JOT_WIDGET=1 jot pick --widget --line "$READLINE_LINE") || return
  READLINE_LINE="$out"; READLINE_POINT=${#out}
}
bind -x '"\C-g": __jot_widget'

# zsh
__jot_widget() {
  local out; out=$(JOT_WIDGET=1 jot pick --widget --line "$BUFFER") || return
  BUFFER="$out"; CURSOR=${#BUFFER}; zle redisplay
}
zle -N __jot_widget; bindkey '^G' __jot_widget

安装走 zoxide / starship 那套一行引导：jot init powershell | iex、eval "$(jot init bash)"。所有 widget 脚本由二进制自己吐出来，用户 profile 里永远只有那一行，升级不用改配置。

05

关键决策

每条都记了代价 —— 这些是以后想反悔时要付的账。

D-01格式
Markdown + YAML frontmatter
理由
它本身就是「笔记本」—— 命令旁边能写为什么、写坑。GitHub 上直接可读可 diff，社区 PR 门槛几乎为零。Atuin Desktop 用纯 YAML，用户当场抱怨太啰嗦，官方已在计划换成 markdown-like。
代价
解析比 TOML 复杂；要防用户把它当自由文档写坏结构。
D-02格式
变量写 {{x}}，不用 <x>
理由
navi 用尖括号，但 < > 是 shell 重定向符，命令文本天然歧义，也破坏语法高亮。
代价
从 navi 迁移需要一个转换脚本。
D-03格式
变量分 ask / profile / shell 三层
理由
这三层解决三个不同问题：临时输入、我自己的环境常量、机器上的实时状态。少任何一层都得手填。
代价
三层的求值顺序和覆盖规则要想清楚并写进 spec。
D-04安全
只注入，永不执行；回车永远由人按
理由
安全模型即产品模型。一个会跑 sudo systemctl 的工具，「我从不执行任何东西，我只是把字打出来」可以直接写进 README 第一屏。Warp 和 Atuin 都是执行模型，这是你唯一且免费的差异化。
代价
放弃「一键批量执行」这类需求，永久性地。
D-05注入
三通道并存，键盘模拟是必需项
理由
SSH 边界之后 widget 通道必然失效（图 2）。要满足「ssh 完接着用」，B 通道没有替代品。
代价
吃下 Wayland、macOS 授权、EDR 误报这三笔长期维护债。
D-06依赖
自带模糊匹配与 TUI，不依赖 fzf
理由
nucleo + ratatui。navi / pet / cheat 全都要外部 fzf，这正是它们在 Windows 上体验垮掉的原因。Windows 一等公民是你最实在的空位。
代价
要自己实现选择器交互，多两三天。
D-07架构
文件是唯一真相，GUI 只是编辑器之一
理由
无数据库、无导入导出、无锁定。用 notify 监听文件热重载，用户拿 vim 改照样生效，git 冲突用户自己 merge。
代价
没有事务，外部改坏文件要能优雅报错而不是崩。
D-08分发
零后端：GitHub tarball + index.json
理由
CI 生成索引发到 Pages，客户端从 codeload.github.com 拉 tarball，不需要 git 也不需要鉴权。零服务器、零账号、零合规负担。tldr 靠同样的模式攒到了几千贡献者。
代价
没有使用数据。这对你是好事。
D-09安全
社区源默认禁用 from: shell
理由
动态变量源 = 任意代码执行，只要预览一下就中招 —— 这是整个品类的漏洞，navi 也有。分级：none（禁用）/ prompt（首次弹完整命令确认，按内容 hash 记忆）/ full（仅本地笔记本）。
代价
社区笔记本体验略打折，值得。
D-10性能
CLI 冷启动预算 50ms，硬指标
理由
widget 路径每次按键都重启进程，慢一点整个体验就废了。落地：~/.jot/index.bin 按 mtime 增量失效；widget 路径上零网络 IO（jot sync 只能手动触发）。
代价
CLI 永远不能用 Node/Python 写，也不能塞进 GUI 进程。
D-11栈
Rust + Tauri v2 + Svelte
理由
CLI 要单文件无运行时依赖，GUI 要能复用同一个 core —— 这个组合是唯一解。navi / espanso / atuin 全是 Rust，注入层的坑可以直接抄。Tauri 产物 ~8MB，Electron ~100MB。
代价
Tauri 的 WebView 在旧 Windows 上偶有差异；Svelte 生态比 React 小。
D-12范围
先做导出器，再做注入器
理由
在写任何平台代码之前，先把笔记本导出成 Windows Terminal 的 sendInput snippets、espanso YAML、shell alias。几乎零成本，让工具第一天就有用，同时观察自己真实的使用姿势。
代价
几乎没有 —— 这是纯赚的。
06

捕获：对抗空笔记本

这是最大的产品风险，而且不是技术风险

这类工具绝大多数死于同一件事：用户装了，然后笔记本一直是空的。所以捕获比存储重要一百倍，M0 就得有。

  • jot save —— 抓上一条命令直接存，绑 Ctrl+Alt+S。widget 模式下能直接拿到当前缓冲区。
  • jot import history —— 扫 shell 历史，按频次排序，交互勾选。Windows 在 %APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt，bash/zsh 各自的 history 文件。导入时自动跳过看起来像 token / 密码的参数。
  • 反向参数化 —— 存 sudo systemctl restart kestrel-orders-api.service 时，jot 发现这个值等于 profile.service，直接问「要不要替换成 {{service}}？」。这一条最讨喜，实现只要一个反向查表。
  • 首启向导：检测已安装的 flutter / npm / docker / git / kubectl，推荐对应的社区笔记本 —— 保证第一次打开就不是空的。

09

M0 落地时定下的事

Q-1

名字 → jot。三个字母，语义正好是「记一笔」。BSD 有个同名小工具，但 Linux / Windows 上这个名字基本是空的。

可改 —— 只需改 [[bin]] name 和四个 shell 集成脚本。

Q-2

热键 → PowerShell Ctrl+J，bash / zsh / fish Ctrl+G。两边不一致是有原因的：Ctrl+J 在终端里就是 LF，在 readline 下等价于回车，绑它会毁掉换行；而 PSReadLine 收到的是独立的按键事件，没这个问题。

jot init bash --key '\C-o' 可以自定义。

Q-3

一个标题下多个代码块 → 各自独立条目。多步骤 runbook 不做，那是 Atuin Desktop 的地盘。

实际写内置笔记本时印证了这个选择：同一件事的 Windows 版和 bash 版本来就该是两条各带 @platform 的独立条目。

Q-4

@confirm → 已实现。460 条内置命令里有 61 条带这个标记。

它和 D-04 一起构成产品的安全叙事：jot 从不执行，且危险的那些还要再确认一次。

Q-5

新问题：{{ }} 与 Go 模板撞车。写 docker / kubectl 笔记本时立刻撞上 —— docker ps --format "{{.Names}}"。

已解决，用户零负担：只有内容是纯标识符的才算变量。{{.Names}} 以点开头、{{range .X}} 含空格，都自动当字面量；{{end}} 这种与标识符同形的由保留字表兜住。有单元测试守着。

Q-6

新问题：GNU host 工具链在 Windows 上编不过 —— dlltool 需要 as，rustup 的 self-contained 目录里没有。

改用 MSVC host（机器上已有 VS 2026 的 C++ 工具链）。README 里记了这个坑。
